# Освітня платформа

React + TypeScript застосунок для перегляду курсів, фільтрації, запису, скасування запису та перегляду власних курсів. Кешування серверних даних реалізовано через TanStack Query.

## Запуск

```bash
npm install
cp .env.example .env.local
npm run dev
```

У `.env.local` задайте адресу API (типово `http://localhost:3000/api`). Очікуються такі endpoint-и:

- `GET /courses?category=...&level=...` — список курсів; обидва фільтри необов’язкові.
- `GET /courses/:id` — деталі курсу.
- `POST /enrollments` із `{ "courseId": "..." }` — запис.
- `GET /enrollments/me` — записи поточного користувача. Відповідь може містити вкладений короткий опис `course`.
- `DELETE /enrollments/:id` — скасування запису.

Для захищених endpoint-ів клієнт додає Access Token із `src/api/authToken.ts`; сервер має повертати JSON без обгортки `data`. Endpoint авторизації та автоматичного оновлення токена в навчальному прикладі немає.

## TanStack Query і кеш

`QueryClientProvider` задає глобальні `staleTime` і `gcTime`; запити списку та деталей задають власні значення. Query Key фабрики включають фільтри курсу або ID, тому кожен варіант фільтра та детальна сторінка мають окремий кеш. Після успішного запису чи скасування інвалідуються записи користувача та курси, які можуть змінитися.

## Токени

Access Token — короткоживучий credential для захищених API-запитів. Refresh Token живе довше й використовується для отримання нового Access Token; автоматичне оновлення в прикладі не реалізовано.

`localStorage` простий, але доступний JavaScript сторінки: XSS може викрасти збережений токен. Не зберігайте там довгоживучий Refresh Token. HttpOnly cookie не читається JavaScript і зменшує ризик прямого викрадення токена, але браузер додає cookie автоматично, тому потрібні належні `SameSite`, `Secure`, CORS і захист від CSRF. HttpOnly не запобігає виконанню шкідливих дій через XSS.

Задайте `VITE_USE_COOKIE_AUTH=true`, якщо backend використовує HttpOnly cookie; сервер має підтримувати credentials і CORS.
